How to run a Kanban board that actually flows

Kanban is a pull system: work is pulled into the next stage only when there is capacity, instead of being pushed in by whoever shouts loudest. A board makes that visible. Three habits make the difference between a pretty board and a productive one:

  1. Make policies explicit. Agree what "Done" means for each column — for example "In progress → Done requires code review and a passing test".
  2. Limit WIP. When the In progress column hits its limit it turns red. Swarm on blocked work rather than starting something new.
  3. Review flow weekly. Look for cards that have not moved. Ageing work is the earliest warning of a problem.

Kanban vs Scrum boards

A Scrum board resets every sprint and holds only the sprint backlog. A Kanban board is continuous; there are no sprints, and the WIP limit — not the sprint length — controls throughput. Read the full Kanban method guide or compare frameworks in Agile vs Waterfall vs Hybrid.

Priority colour key

Red left border = high priority, amber = medium, teal = low. Keep high-priority cards rare — if everything is urgent, nothing is.

Frequently asked questions

What is a WIP limit?

A work-in-progress limit caps how many cards can sit in a column at once. When the column is full, the team finishes or unblocks work before pulling anything new. This shortens cycle time and exposes bottlenecks.

What WIP limit should I start with?

A common starting point is the number of people on the team for the In progress column, then lower it gradually until flow improves without people sitting idle.

Can I use this board on my phone?

Yes. On touch devices, use the ← and → buttons on each card to move it between columns.
